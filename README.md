# epaper-clock

Waveshare **ESP32-S3-ePaper-3.97** 的节能时钟固件，使用 **ESP-IDF 5.5.2**。
功能：时钟、日期、温湿度、电量、每日 NTP 校时、BLE 配网、按键开启的局域网 HTTP 管理。
**只以 Wi-Fi STA 模式加入用户的路由器，不创建热点。** 音频和用户闹钟已移除。

## 首次设置：HTTPS 网页 → BLE → 路由器

配网页：**https://billxc.github.io/epaper-clock/**（GitHub Pages，已启用 HTTPS）

仓库已公开，并按维护者授权保留原始提交历史及作者邮箱。

1. 首次没有 Wi-Fi 配置时，手动开机进入 BLE 配网。屏幕显示设备名与 **6 位纯数字一次性校验码**（如 `042731`）。
2. 手机/电脑打开上面的 HTTPS 页面，点击连接设备，选择屏幕上的 `PROV_EPAPER_…`。
3. 输入屏幕校验码、家中 **2.4GHz Wi-Fi** 的 SSID 和密码，提交。
4. 设备通过路由器取得 IP 后，才保存新配置；关闭 BLE，尝试校时并进入局域网管理。
5. 屏幕显示路由器分配的 IP 与临时 HTTP 密码。在同一局域网打开 `http://<屏幕IP>/`，
   HTTP 用户名 `admin`，密码使用屏幕的临时密码，**不是路由器密码**。

配网会话最多约 5 分钟（不含异常硬件阻塞）。失败或超时保留之前成功保存的 Wi-Fi 配置。
页面不会保存或上传 Wi-Fi 密码；密码只通过 BLE 发送到所选设备。
采用 ESP-IDF **Security1（X25519 + PoP + AES-CTR）**，不支持明文 Security0 降级。

### 浏览器兼容性

- 使用支持 **Web Bluetooth 和 WebCrypto X25519** 的新版 Android/桌面 Chrome 或 Edge。
  页面会检测能力，不支持时不假装配网成功。
- 普通 iPhone/iPad 浏览器通常没有 Web Bluetooth；可使用乐鑫官方 **ESP BLE Provisioning** App，
  选择屏幕设备名并输入同一个校验码（Security1）。
- 不要从设备的普通 HTTP 管理页启动网页蓝牙；配网入口是独立的 HTTPS Pages 页面。
- 屏幕校验码必须输入正确。配网时保持设备供电，不按 BOOT 重新上电。

## 按键与日常行为

| 场景 | 操作 |
| --- | --- |
| 首次无 Wi-Fi 配置 | PWR 手动开机进入 BLE 配网 |
| 已配置，电池关机状态 | PWR 手动开机，连接路由器并开启 HTTP 管理 |
| 更换路由器 / 密码不对 | 按住拨轮上键（GPIO4）再用 PWR 开机，重新 BLE 配网 |
| USB 时钟运行中 | 拨轮中键（GPIO5）开启 LAN HTTP，上键（GPIO4）开启 BLE 配网 |

PMU 关机后，普通拨轮不能直接给主控上电；电池待机需使用 PWR。
按住 BOOT 上电会进入下载模式，不是管理模式。
USB 启动先保留 10 秒串口校时窗口，再进入对应功能。

HTTP 管理仅提供状态、立即校时、退出。Wi-Fi 凭据通过 BLE 设置，不通过 HTTP 传输。
管理 **闲置 5 分钟退出，单次最长 15 分钟**；自动状态轮询不延长闲置时间。
退出后关闭 HTTP 和 Wi-Fi，恢复时钟并强制全刷，避免管理画面污染刷新缓存。
连接路由器失败时不会开启备用热点，请使用上键重新 BLE 配网。

## 每日校时和节能

电池日常流程：

```text
RTC 每分钟唤醒 → 判断当天是否到校时时间
→ 仅在需要校时时短暂打开 STA，成功或失败后关闭
→ 读取时间/温湿度/电量 → 刷新屏幕 → 屏幕休眠并断电
→ 保存帧缓存并卸载 SD → 设置下一分钟 RTC 唤醒 → PMU 关机
```

- 默认本地时间 **08:00** 自动校时；若当天尚未尝试，08:00 后首次更新补做。
- 每个本地日最多一次**自动尝试**。连接最多等待 15 秒、NTP 最多等待 10 秒；
  失败不每分钟重连，管理页「立即校时」可主动重试。
- 成功后写回 PCF85063。NVS 仅在配置、每日尝试、成功校时时写入，跨断电保存调度状态。
- RTC 无效时先 BLE 配网校时或 USB 校时，不把编译日期当作准确时间。
- 不常驻 BLE、不常驻 Wi-Fi、不初始化音频/IMU、不保留 5ms 按键任务。
- 去掉音频关机清理的约 600ms 等待和温湿度测量前多余的 100ms 等待。
- SHTC3 采样后休眠；不使用未经校准的固定温度偏移。

保留整点/半点全刷，其他分钟「旧帧恢复 + 新帧」双次整屏范围局刷。
SD 每分钟仍有挂载与约 48KB 读写开销，**不是极限低功耗方案**。
缓存为 SD 根目录 `/epaper-clock-v1.bin`；不会格式化卡或扫描其他文件。
无卡或缓存缺失时退回全刷，可能更耗电、闪烁更多。
USB 模式保持运行并检查按键，其功耗不能用于推算电池续航。

## 构建与烧录

```sh
# 在已经安装的 ESP-IDF v5.5.2 环境中
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash
```

默认：16MB Flash、Octal 8MB PSRAM、160MHz、NimBLE、USB Serial/JTAG。
`partitions.csv` 为 3MB 应用预留空间。`menuconfig` → `Clock` 可设置时区、校时小时、NTP 服务器；
默认 `CST-8`（UTC+8），改变时区后重新校时。

公开仓库的 `Firmware` workflow 使用官方 ESP-IDF 5.5.2 容器编译并上传固件产物。
固件提交 `d4cefd5` 已通过 [ESP-IDF 5.5.2 完整构建](https://github.com/billxc/epaper-clock/actions/runs/39194768407)，
可在该运行的 Artifacts 下载 `epaper-clock-firmware`。源码检查、协议单测和浏览器模拟不等于实机验证。
**目前未进行本板烧录、真实 BLE/路由器联调和电池功耗测量，不承诺具体续航天数。**

板级电源沿用官方公布的电压/充电配置。文档称 TG28，示例使用 AXP2101 接口；
实际兼容性仍需对照板卡确认，本项目不能用于任意 ESP32 板。烧录会替换旧固件。

### USB 备用校时

正常接 USB 开机，在最初 10 秒内（先关闭串口监视器）：

```sh
uv run --with pyserial python tools/set_time.py /dev/ttyACM0
# Windows: 使用 COM5 这类串口名
```

收到成功确认才代表 RTC 已设置；主机时间需准确。有 RTC 备用电池可在更换主电池时保时。

## 安全、隐私和许可

- Pages 仅托管静态资源；不使用分析统计，不向托管方提交凭据，不用浏览器存储保存密码。
- BLE 只在物理触发/首次设置时短时开放，每次会话重新生成 6 位数字 PoP；短码优先方便输入，仅面向可信近距离配网。
- HTTP 使用临时 Basic 认证，但**没有 TLS**，仅限可信局域网，不开放公网端口。
- Wi-Fi 凭据存在设备 NVS，未启用 Flash 加密，不抵御物理读取。
- 已检查源码快照及历史文件，不含个人 Wi-Fi、真实设备数据或本机路径；原提交作者邮箱按授权保留。
- 新代码为 MIT，第三方驱动保留原许可，来源见 [THIRD_PARTY.md](THIRD_PARTY.md)。
