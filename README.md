# epaper-clock

Waveshare **ESP32-S3-ePaper-3.97** 的精简节能时钟固件，基于 **ESP-IDF 5.5.2** 开发。
保留大字时钟、日期、温湿度和电量，支持每天联网校时及按需开启的 HTTP 管理页面。
不是官方八合一应用的完整移植。

> **当前状态：未完成 ESP-IDF 编译、烧录及实机验证。** 本机没有对应工具链；
> 已做源码依赖检查及管理页沙箱浏览器模拟测试，但不能代替固件编译和设备端联调。
> 节能改动有源码依据，没有实测续航数据，
> 不承诺 30 天、60 天或一定超过官方的「1500mAh 时钟模式 15 天以上」。

## 保留与删除

| 保留 | 删除 |
| --- | --- |
| 每分钟更新 HH:MM、日期、SHTC3 温湿度 | 音频、麦克风、I²S、扬声器、用户闹钟 |
| 电量显示、PCF85063 RTC、PMU 关机 | BLE、天气、日历应用 |
| 每日 NTP / USB 校时，默认 UTC+8 | 阅读器、文件浏览器、菜单、IMU 驱动 |
| 按键开启 Wi-Fi HTTP 管理，NVS 保存配置 | 常驻服务器、常驻 Wi-Fi、5ms 按键扫描任务 |
| SD 刷新缓存 | SD 字库、图片素材、SPIFFS |

**用户闹钟已移除，但 RTC 定时唤醒仍保留**：这是低功耗时钟自动更新所必需的。

## 工作流程与节能边界

电池供电：

```text
RTC 每分钟唤醒 → 初始化 I²C、PMU、SD、屏幕、SHTC3
→ 判断当天是否到校时时间（仅到期时短暂启用 Wi-Fi、完成后关闭）
→ 恢复旧画面 → 读取时间/温湿度/电量 → 更新画面
→ 屏幕休眠并关闭 ALDO3 → 保存缓存并卸载 SD
→ 设置下一分钟 RTC 唤醒 → PMU 关机
```

与官方示例相比：

- 不再每分钟初始化音频设备，不再执行音频关机清理中的约 600ms 延时。
- 不初始化 IMU、不启动菜单和 5ms 按键轮询任务；普通分钟不启动 Wi-Fi。
- Wi-Fi 只在每日校时或管理会话开启，退出后停止驱动；不反复写 NVS 保存页面状态。
- SHTC3 删除测量前额外 100ms 等待，完成读取后立即休眠；保留 CRC 校验。
- 所有绘图资源内置；不加载字体或图片，不反复写 ESP Flash 保存页面状态。
- 保留官方**整点/半点全刷、其他分钟两次整屏范围局刷**的方式，
  不在未验证控制器行为前贸然删掉旧帧恢复刷新。屏幕命令和等待时序未改。

**SD 卡仍有每分钟挂载和约 48KB 读写开销**，不是极限低功耗方案。
首版优先删除明确无用的工作，不同时重写供电架构、局刷波形或任意关闭电源轨。
SD 缓存文件为根目录 `/epaper-clock-v1.bin`；不会格式化卡或读取其他文件。
无卡、缓存缺失或读取不完整时，退回全刷，仍可显示，但功耗和闪烁会增加。

USB 供电时，启动后留 **10 秒校时窗口**，随后根据启动原因进入管理或时钟。
时钟模式保持运行，每分钟更新，等待期间每 50ms 检查拨轮中键。
USB 供电模式不代表电池续航；测功耗请拔掉 USB，避免日志线/调试器反向供电。
温度未沿用官方固定 -1.5℃ 偏移，外壳自热误差需实测后再校准。

## 每天联网校时

- 先在管理页面配置 2.4GHz Wi-Fi。默认本地时间 **08:00** 校时；若当天尚未尝试，
  08:00 后首次更新也会执行。`menuconfig` → `Clock` 可修改小时和 NTP 服务器。
- 每个本地日最多进行一次**自动尝试**；失败当天不每分钟重试，可在管理页面主动重试。
- STA 连接等待最多 15 秒、NTP 等待最多 10 秒，失败继续显示 RTC 时间并关闭 Wi-Fi。
- 校时成功写回 PCF85063。NVS 仅在配置、每日尝试或校时成功时写入，
  跨 PMU 关机仍记得当天是否尝试过；手动校时/修改配置可额外触发联网。
- 初次 RTC 无效时不猜测日期，请在管理页面「立即校时」，或使用 USB 设置时间。

## 按键开启 HTTP 管理

**电池供电且已关机时**，普通拨轮不能给主控上电。长按 **PWR** 手动开机进入管理：
固件在清除 RTC 标志前区分定时唤醒与手动启动，手动启动不直接返回分钟更新模式。
如接 USB，先经过 10 秒 USB 校时窗口。USB 时钟运行中按**拨轮中键（GPIO5）**也可进入。
电池模式也会在醒来时检查中键，但关机期间按中键不会立即唤醒。

1. 屏幕显示设备 AP 的 SSID、每次会话随机生成的密码和 `192.168.4.1`。
2. 手机连接该 WPA2 热点，浏览器打开 **http://192.168.4.1/**。
3. HTTP 登录用户名 **`admin`**，密码与屏幕上的热点密码相同。
4. 页面可查看设备时间、STA 连接状态/IP 和上次校时；配置 Wi-Fi、立即校时、退出管理。
   保存 Wi-Fi 会退出管理并尝试校时，之后恢复节能时钟。

已配置路由器时，管理模式也尝试接入 STA；若连接成功，同一可信 LAN 可通过页面显示的
STA IP 访问。配网失败不影响通过设备 AP 继续操作。
页面不回显保存的 Wi-Fi 密码，不把密码写进浏览器本地存储或日志。

**5 分钟无操作自动退出，单次会话最长 15 分钟**。状态自动轮询不延长闲置时间。
HTTP 服务器和 AP 只在管理会话存在，退出后恢复时钟并关闭 Wi-Fi。
进入管理会破坏原先屏幕画面，因此退出后强制全刷，不沿用旧缓存局刷。

这是**可信本地网络配置入口**：HTTP 没有 TLS，不开放公网端口；
热点用随机 WPA2 密码，HTTP 路由需要 Basic 认证，POST 仅接受 JSON、不启用 CORS。
已保存的 Wi-Fi 凭据存于设备 NVS，未启用 Flash 加密，不抵御物理读取。

## 构建与烧录

需要已安装的 ESP-IDF **v5.5.2**，以及有权访问 USB 设备的开发机。
先确认实际硬件型号和 PMU 兼容性：文档写 TG28，官方代码使用 AXP2101 驱动；
本项目沿用该驱动及充电参数，**未独立确认两者的对应关系，不适用于任意 ESP32 板**。

```sh
# 进入已有的 ESP-IDF 环境后执行
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash
```

默认板卡参数：16MB Flash、Octal 8MB PSRAM、160MHz CPU、USB Serial/JTAG。
`idf.py menuconfig` → `Clock` 可修改 POSIX 时区，默认 `CST-8`（UTC+8）；
改变时区后需重新校时。Windows 串口使用 `COM5` 这类名称。
烧录会替换当前固件；本项目不会替用户执行烧录。

## USB 校时

RTC 必须先设置一次；如有备用电池，换主电池后仍可保留时间。
没有有效 RTC 时间时，屏幕提示 `SET TIME WIFI/USB`，不把编译时间冒充准确时间。
USB 是无需网络的备用校时方式，日常漂移由每日 NTP 校正。

接 USB 后正常重启/开机，在 10 秒内运行：

```sh
# 使用已有 pyserial 环境，或用 uv 临时提供脚本依赖
uv run --with pyserial python tools/set_time.py /dev/ttyACM0
# Windows: uv run --with pyserial python tools/set_time.py COM5
```

输出 `RTC set from host time` 才代表成功。主机时间必须准确。
串口监视器应先关闭，不能和脚本同时占用串口。
不要按住 BOOT 再上电尝试校时，那会进入下载模式而不是运行本固件。

## 实机验收（待完成）

1. 用 ESP-IDF 5.5.2 编译；核对 PMU 初始化和 SD 挂载结果。
2. 校时后断开 USB，用电池验证至少三次自动唤醒/刷新，以及跨整点、跨日行为。
3. 验证 PWR 开机 / USB 拨轮按键进入管理，配网、HTTP 登录、保存、立即校时、退出及超时。
4. 跨天验证每日一次自动校时；断网时不每分钟重试；每次退出后 AP/HTTP 不可访问。
5. 验证温湿度合理、全刷/局刷无异常残影，无卡退回全刷能工作。
6. 电池端测 **关机电流 + 一个完整分钟周期电量**，与同板/同电池官方固件对比。
   日志 `Update finished in ... ms` 仅代表软件路径时长，不是电量测量。

优先确认关机静态耗电及每次启动/屏幕刷新耗电占比，再决定是否移除 SD、
优化旧帧恢复、减少全刷，或比较 ESP deep sleep 与 PMU 冷启动。

## 目录

- `main/`：更新流程、RTC 调度、绘图、每日 NTP / Wi-Fi 生命周期、按需 HTTP 管理页面。
- `components/`：精简后的板级 I²C、PMU、墨水屏、SD 缓存、SHTC3 驱动。
- `tools/set_time.py`：USB 校时工具。
- `THIRD_PARTY.md`：上游版本及许可说明。
