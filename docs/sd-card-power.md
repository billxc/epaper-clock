# TF / microSD 卡电耗调研

范围：本项目无灰度模式的“每分钟冷启动，挂载现有 exFAT / FAT32 卡并打开或新建缓存，按需读旧帧，刷屏，再写新帧、同步、卸载并关机”。当前缓存已通过完整固件构建和真实 FatFs exFAT 镜像测试，尚无实卡、功耗或时序验收结论。下文区分当前源码流程、厂商规格、外部实测和条件换算；外部文献不是本板测量。两种灰阶正常整屏刷新不初始化、挂载或读写 SD（用户明确选择自动调试时除外），本文的读写收支主要对应默认无灰度路径，见 [渲染说明](rendering.md)和 [SD 缓存与边界](sd-cache.md)。

## 结论

1. **不能按容量大小预测耗电。**已查到的 microSD 厂商规格没有同系列逐容量电耗对照；外部实测说明，同容量卡也可能明显不同。
2. **初始化、文件系统操作、写入长延迟和供电时长都不能忽略。**48KB 除以标称 MB/s，不能代表一次完整保存的耗电。
3. **必须比较整周期积分电荷，而不是峰值电流。**SPI 的结果不能直接移植到本项目的 4-bit SDMMC；快卡也可能以更高电流、更短时间完成工作。
4. **高耐久、工业级、小容量都不是低功耗保证。**要看具体型号及实际工作模式，不能仅凭标签采购。
5. 目前没有足够依据宣称“TF 一定比内部 Flash 省电”，或“固定窗口无 TF 一定更省电”；刷新波形和主控额外运行时间仍决定总收益。

## 1. 当前源码流程

源码：[sdcard_bsp.c](../components/sdcard_bsp/sdcard_bsp.c)、[缓存 API](../components/sdcard_bsp/fat_frame_cache.h)、[main.c](../main/main.c)。

- 使用 **4-bit SDMMC**，请求 High Speed，上限 **40MHz**；卡和驱动可能协商较低频率，不是 SPI，也不是 UHS-I SDR104。
- 使用 SDK 5.5.2 自带 FatFs R0.15，项目内启用 `FF_FS_EXFAT`、heap LFN 与 UTF-8，不修改共享 SDK；同一驱动支持现有 exFAT 和 FAT32 卷。不需要电脑准备工具、重新分区或格式化，也不要求删除视频。挂载失败不 format、fdisk 或 repair，直接放弃缓存并全刷。边界见 [SD 缓存](sd-cache.md)。
- 普通文件 API 在卷根目录打开 `epaper-cache.bin`，不存在时排他新建并初始化。容器固定 **65536 字节**，EPDCACHE 版本 1，包含 512 字节头和偏移 512 的 **48000 字节**单色帧。已有同名文件若大小或头身份不识别则拒绝、不覆盖，已识别缓存不截断。新建会更新目录/分配元数据，文件写入与同步也可能更新元数据；不能声称缓存外所有字节不变或绝对不影响视频。
- 无灰度按需初始化卡、挂载卷并打开缓存；**并非仅时钟初始化 SD**：初始化/配网、BLE/LAN 管理、菜单或消息等单色画面在传输前也会尝试挂载并失效旧缓存，保证不误信与玻璃不符的基线。普通 RTC 分钟路径先检查每日校时再按需挂载；坏卡/无卡不再永久锁存本 boot，而是后续请求至少间隔 5 秒重试；失去基线信任后的菜单失效也限频 5 秒。正常灰阶不初始化、挂载或读写 SD（显式自动调试可测试独立文件；失败回退到单色后按单色处理）。为避免换卡沿用旧 FIL/cluster，每次同步缓存操作结束即关闭/卸载/释放，读旧图、显示前失效、写新图可能多次初始化，增加的耗时与能耗待测。
- 全刷轮次跳过旧帧读取；只有需要局刷且缓存头和帧 CRC 均有效时才使用旧帧，否则全刷。单色显示前先持久失效，实际显示成功且无遮挡后按 invalid → payload → valid 提交；同一打开句柄内已成功同步的失效头不重复写入/同步，最终有效头仍必须同步。失败或重新打开不继承这项去重保证，不删除文件。
- 若假设每轮均读取、写入一帧，1440 轮/日的帧负载读取和写入**各约 69.12MB/日**；实际全刷会跳过读取，另有头、扇区对齐、文件系统元数据读写、同步及命令开销。这不是卡总线实测流量，也不是每天新增一个 69MB 文件。
- 每次缓存操作后关闭文件、卸载 FatFs 并释放 SD 主机；失败丢弃脏缓冲而不重试旧句柄 flush。电池模式最后再请求 PMU 关机；USB 模式不走这个关机分支，但也不保留跨操作 SD 句柄。**卸载或主机清理不等于物理断开卡电源。**卡电源轨和关机后的残余电流仍未核验。
- 不扫描整张卡的视频内容，也不主动修改或删除其他文件；卡容量增加不会让帧负载按容量成比例增加，但目录查找与分配开销仍取决于卷状态。固定文件覆盖不等于卡内部 FTL 没有写放大或掉电风险。

### ESP-IDF 路径与测量边界

- [sdmmc_init.c（v5.5.2）](https://github.com/espressif/esp-idf/blob/v5.5.2/components/sdmmc/sdmmc_init.c)：初始化包含 OCR、CID/CSD、总线宽度、速度协商等，不是单纯等待供电稳定。
- [sdmmc_cmd.c（v5.5.2）](https://github.com/espressif/esp-idf/blob/v5.5.2/components/sdmmc/sdmmc_cmd.c)：不能 DMA 的缓冲区可能转为内部临时缓冲。当前缓存文件层使用静态对齐 4KiB 缓冲分批读写，FatFs 负责元数据、分配映射及扇区缓冲；不把 PSRAM 中的 48KB 帧假定为一次大块 DMA。文件 API 调用数量不等于实际 SDMMC 命令数量；实际时序、命令开销与能耗仍需测量。

CRC 与头最后提交用于拒绝不完整/损坏缓存，不等于原子文件系统或卡内掉电保护。exFAT 无日志，`f_sync` 不能代替真实掉电后卷与视频完整性的硬件验证，也没有证明净节电收益。最新问题结论见 [对话疑问记录](questions.md)。

## 2. 厂商原始规格：只能按原文条件使用

### Delkin SLC microSD，U331C / U300

[官方规格书，2021 年 1 月，第 2 页](https://www.delkin.com/wp-content/uploads/2021/01/microSD-Industrial-Spec-Sheet-Jan-2021.pdf)

| 项目 | 原文 |
| --- | --- |
| 供电范围 | 2.7–3.6V |
| 读取电流 | `typically < 50mA` |
| 写入电流 | `typically < 100mA` |
| Idle 电流 | `typically < 500µA`，即 0.5mA |

这是典型描述，**不是保证最大值**。文件没有明确这些电流对应的精确电压、时钟和温度。U331C 列有 128MB 至 4GB 等不同容量料号，但没有逐容量电流比较。

### Transcend USD410M

[厂商规格书，Conrad 托管副本，第 6 页](https://asset.conrad.com/media10/add/160267/c1/-/en/002302642DS00/datasheet-2302642-transcend-ts8gusd410m-pamaetova-karta-micro-sd-8-gb-class-10-uhs-i.pdf)

| 模式 | Read Max | Write Max | Idle Max |
| --- | ---: | ---: | ---: |
| Default，25MHz | 100mA | 100mA | 0.5mA |
| High Speed，50MHz | 200mA | 200mA | 0.5mA |

该表引用 SDA 规范，是 **Max 模式规格，不是短写实测平均**。不能将 200mA 乘以整个刷新周期作为卡耗电，也不能假定本项目 40MHz 电流就是 50MHz 的 80%。

同一副本第 15–17 页说明：检测到最低供电电压后，约 1ms 内可接收首条命令，还需要时钟和初始化协议。**这不是“1ms 后文件系统就挂载完成”**。该产品没有给出本场景的初始化总电荷或逐容量电流曲线。

以上均为历史版本。今天买到的同名产品可能已经更换 NAND、控制器或固件，不能将历史规格当作任意新卡的实测。

## 3. 外部实测：有明确平台，但不是本板结果

### Gough’s Tech Zone，2021

[Experiment: microSD Card Power Consumption & SPI Performance](https://goughlui.com/2021/02/27/experiment-microsd-card-power-consumption-spi-performance/)

SPI 电流测试使用 Arduino MKR1010、12MHz SPI、SdFat benchmark，卡单独以 3.3V 供电，用 Rohde & Schwarz NGM202 以 500kS/s 记录。下表是作者对波形的估计：

| 卡样品 | benchmark 活动平均电流 | benchmark 结束后仍供电的电流 |
| --- | ---: | ---: |
| SanDisk Ultra 16GB A1 | 约 24mA | 约 1.25mA |
| Verbatim Premium 16GB V10 | 约 20mA | 约 1.45mA |
| Delkin Industrial SLC 1GB | 约 22mA | 约 0.15mA |

同为 16GB，活动和静置电流的排序相反；1GB 工业卡的活动平均值也没有明显更低。这不能证明某一容量天然更省电。

作者随后用改装读卡器测试原生总线：SanDisk / Verbatim 的 UHS-I 测试最高平均约 80mA；Delkin 使用较慢的原生 4-bit SD，写约 60mA、读约 40mA。**同一张卡在不同总线/负载下，电流并不是固定常数。**

限制：SPI 测试采用 100mA 量程，部分尖峰削顶；没有四线供电感测，且为观察波形未加本地去耦，不能当成最终产品的推荐接法。原生总线测试也不是 ESP32-S3 40MHz、48KB 短文件。文中“sleep”是测试结束后的状态称呼，不应自动当成某个标准深睡模式。

### Cave Pearl Project，2017，含后续补充

[Cutting Power to Secure Digital Media cards for Low Current Data Logging](https://thecavepearlproject.org/2017/05/21/switching-off-sd-cards-for-low-power-data-logging/)

在同一低功耗记录器和同一初始化/打开/关闭序列下：

- SanDisk 256MB：活动波形约 65ms，电荷小于 3mA·s。
- SanDisk 2GB：活动波形约 156ms，电荷超过前者两倍。
- 另一组 4KB CSV 保存实验中，不同卡的保存电荷差异超过 5 倍。

这里的 65/156ms 是**组合操作**的活动时段，不是单纯供电启动时间；4KB 保存还夹有其他外设操作，不是连续大块写。后续测试同为 128MB 的不同品牌卡也有明显波形差异。

平台是旧式 Arduino SPI。后续部分实验使用较大分流电阻并有量程削顶，可能扰动供电，因此不照搬其峰值或给卡做采购排名。本文只引用它证明：**每次重新初始化的代价以及卡间差异真实存在**。

## 4. 对本机意味着多少电：条件换算，而非测量结果

卡单支路应积分完整供电周期：

```text
Q_card = ∫ I_card(t) dt
覆盖：上电/初始化、文件系统挂载、目录查找/必要时创建分配、头与帧读写/同步/忙等待、卸载、写后活动、等待期间，直到实际断电。
```

按 1440 轮/日：

```text
每天卡端电量 [mAh] = 每轮电荷 [mA·s] × 0.4
```

| 假设实测得到的每轮总电荷 | 每天卡端电量 | 卡端 3.3V 下每天能量 |
| ---: | ---: | ---: |
| 5mA·s | 2mAh | 6.6mWh |
| 20mA·s | 8mAh | 26.4mWh |
| 50mA·s | 20mAh | 66mWh |

**这三行只是换算情景，不是本板测得范围，也不是厂商保证的上下限。**电池端还要考虑供电路径、变换损耗、ESP32 额外运行时间，不能直接将卡端 mAh 与主电池容量相减。

### 静置差异应乘以实际供电时间

仅作敏感性分析：如果每轮有 5 秒卡空闲但仍供电，沿用 Gough 在 SPI 测试结束后测到的电流：

| 示例电流 | 5 秒/轮、1440 轮的电量 |
| ---: | ---: |
| 0.15mA | 0.30mAh/日 |
| 1.25mA | 2.50mAh/日 |
| 1.45mA | 2.90mAh/日 |

这不是本机预测。它说明低静置电流有帮助，但**本机若每分钟确实断电，就不能拿 24 小时常供电的 30–35mAh/日吓大其收益**。反过来，若卡没有真正断电，结果又会完全不同。

### ESP32 多运行的时间也要算

若存储操作让主控额外运行 0.2 秒，假设该阶段整机电流为 80mA，则贡献约：

```text
80mA × 0.2s × 1440 ÷ 3600 = 6.4mAh/日
```

80mA 和 0.2 秒仍是假设，不是本板数据。不要把它与“卡单支路”混成同一种测量，也不要在已测得整机电流后再次叠加卡电流。

## 5. 本项目最值得做的事情

先测现有卡，不必先购买小容量/工业卡。用同一张卡、同一正常分钟刷新流程，记录：

1. **电池端完整一轮的能量**，包含启动、屏幕、存储和关机后的底电流。
2. 能单独测卡支路时，再积分卡从上电到实际断电的电荷；标出初始化/定位、读、帧写入、头提交、忙结束、主机清理和断电。
3. 同时记录各阶段耗时，识别偶发长延迟；供电稳定性和测量分流压降不能影响结果。

**不能简单用“拔卡后的整机电量差”当卡耗电**：当前无卡会退回全刷，屏幕刷新策略已经变化。比较卡间电耗要控制相同刷新类型；比较 TF 与无 TF 窗口方案，则要比较各自完整流程。

当前源码跳过全刷旧帧读取，正常 SD 访问用于单色时钟及非时钟页面的显示前失效（显式自动调试例外），并通过普通文件 API 更新固定缓存；首次创建及后续同步的文件系统开销也必须计入。构建和镜像测试已通过，但它们不是功耗或实卡时序验收结论。后续应评估：

- 初始化、挂载、目录查找/创建分配、分批 I/O、同步及写后尾延迟的实际电荷；是否能更早断电取决于电路，不能用主机清理 API 代替电源开关。
- DMA 缓冲路径与传输粒度，避免过多小块命令；性能优化必须以总能量为准，不能只降总线频率。
- 头最后提交、CRC 拒绝与显示失败失效路径，以及真实掉电后的全刷恢复；不把缓存提交顺序或同步等同于文件系统原子更新。
- 无 TF 固定窗口擦白/重画的可靠性及总耗时，再与当前双次局刷比较。

没有卡支路电源控制和断电保持时间证据前，不加任意“写完立即断电”优化，也不照抄其他 SPI 日志器的等待秒数。
