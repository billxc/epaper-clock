# USB 安装、LAN OTA 与回滚

固件已通过 ESP-IDF 5.5.2 构建、二进制分区表核验及软件测试。**尚未完成真实设备刷入、OTA／断电／回滚验收。**

## Flash 布局

16MiB Flash 使用两个等大的 7.5MiB OTA 应用槽，尾部 896KiB 未分配，不创建文件系统：

| 内容 | 地址 / 大小 |
| --- | --- |
| NVS | `0x9000` / `0x6000` |
| PHY | `0xf000` / `0x1000` |
| OTA 状态 | `0x10000` / `0x2000` |
| OTA A | `0x20000` / `0x780000`（7.5MiB） |
| OTA B | `0x7a0000` / `0x780000`（7.5MiB） |
| 未分配尾部 | `0xf20000` / `0xe0000`（896KiB） |

## USB 安装

[Firmware 构建与下载](https://github.com/billxc/epaper-clock/actions/workflows/firmware.yml) → 最新成功构建 → Artifacts → `epaper-clock-firmware`。
当前应用约 2.708MiB，每槽剩余约 4.792MiB；实际文件及大小以该构建产物为准。

产物包括：

- `epaper-clock-factory.bin`：USB 安装合并镜像，烧到 `0x0`，不是 OTA 文件。
- `epaper-clock.bin`：独立应用，用于 LAN OTA。
- bootloader、二进制分区表、`ota_data_initial.bin`、`flash_args`、`flasher_args.json`。
- `partitions.csv`：可读布局说明，不是烧录文件。

可用乐鑫 Flash Download Tool 或 ESP-IDF 的 `idf.py flash`。若不能自动进入下载模式，按住 BOOT 重新上电。
BOOT 是下载键；上键配合 PWR 是业务初始化入口，两者不同。

**合并镜像会覆盖其包含的 Flash 范围和填充间隙，可能清除 NVS 配置。**需要保留配置时，使用同包 manifest 指定的独立文件，不做整片擦除：

| 独立文件 | 地址 |
| --- | --- |
| `bootloader/bootloader.bin` | `0x0` |
| `partition_table/partition-table.bin` | `0x8000` |
| `ota_data_initial.bin` | `0x10000` |
| `epaper-clock.bin` | `0x20000` |

使用可靠 USB 供电，操作前保存需要的固件与配置。始终使用同一构建包，不混用 bootloader、分区表、启动数据和应用。
安装后可在 LAN 页面检查「OTA 槽容量」：当前和另一槽均应为 **7.50MiB**，数值来自设备实际运行的分区表。
USB 安装初始化 A 槽；第一次正常 OTA 完成后，两槽各有一份可启动应用。

## LAN OTA

1. 长按中键，选择 LAN 管理；手机或电脑打开屏幕上的 IP，以屏幕显示的固定管理密码登录。
2. 选择本项目的独立应用 `epaper-clock.bin`，点击上传升级。
3. 页面显示上传、校验和重启状态；屏幕提示“正在升级，请勿断电”。
4. 启动检查通过或回滚后恢复 LAN，浏览器使用同一管理密码重连并显示结果。
5. 按通常规则，连续五分钟无用户操作返回时钟。

OTA 只写非运行应用槽，不修改 bootloader、分区表或配置。它不自动下载远程版本，也不提供在线改表功能。
Pages BLE 页面只设置 Wi-Fi 和时间，没有 OTA 上传入口。
升级中暂停闲置退出和模式切换；建议 USB 稳定供电。若路由器改变 IP，查看屏幕并用新地址访问。

## 上传与启动保护

- 流式写入，缓冲区约 4KiB，不把整个镜像放 RAM。
- 按实际目标槽大小检查镜像，验证芯片、项目名、完整格式及校验值；拒绝 bootloader、分区表、合并镜像和其他项目。
- 这不是发布者数字签名验证，只适用于可信 LAN。
- 上传中断或校验失败会 abort，不切启动槽；原应用继续运行，管理闲置计时重新开始。
- 完整校验后才保存本次恢复记录并切换启动槽。HTTP 响应尝试完成后由主任务延迟重启。
- 连接中断不等于升级失败：可能已经重启，网页会重新查询，不把未确认结果报成成功。

启用 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`。新应用首次处于 pending verification 时：

1. 完成本地 NVS、I²C/PMU、RTC、UI/显示端口与帧缓冲初始化。
2. 在约 20 秒任务看门狗预算内完成首次显示刷新。
3. 到达本地检查点才标记有效，发生在任何分钟 PMU 关机之前。
4. 确认失败时请求回滚；回滚不可用时停在 USB 恢复提示，不继续正常分钟关机。

Wi-Fi 离线、NTP 不通、RTC 未设日期、缺可选 SD 不作为坏固件条件。启动自检不是全部功能自测；
确认有效后的任意后续故障不承诺自动回滚。可回滚的备用槽必须包含有效应用，不能把空槽当成恢复镜像。

## 升级结果恢复

`clock_ota` NVS 记录本次目标地址、镜像哈希、版本及本次使用的 HTTP 密码，不存上传文件；v1 记录布局保持不变，供回滚镜像读取。
启动时核对运行槽和哈希，区分成功或回滚；暂时开启 LAN，避免被分钟关机抢先关闭。
离开恢复管理后仅清除本次事务，不删除 `clock_lan` 中的固定管理密码；普通分钟启动不反复写 Flash。
按住上键开机的强制初始化优先于恢复管理；仍会先处理新镜像的健康确认，不重置已保存的固定密码。清除临时恢复入口前也必须先迁移/核对凭据，失败则保留事务，不能先删除旧密码再随机生成一个。

固定密码首次由 RF 活跃时的硬件随机数生成（16 个 base64url 字符，96 位随机量），仅在 NVS 提交成功后启用 HTTP。后续读取只读 NVS，不每会话换密码；普通配网和强制初始化也没有密码重置动作。凭据损坏、读取/保存失败时不开 HTTP，不改用随机备用密码；屏幕仍可显示已成功载入的密码，日志不输出它。

从旧版升级时，如果尚无固定密码且存在有效旧 OTA 恢复密码，就先将该密码持久化，再恢复管理，避免重启后凭据突变。如果固定密码已经存在，恢复记录必须与其一致；冲突时停止 HTTP 启动，不接受临时覆盖，也不随机替代。旧版回滚镜像仍遵循其原有代码：v1 事务期间可复用密码，但退出恢复后的跨会话固定行为只由新版保证。降级到旧版不等于给旧固件补上持久化功能。

## 主机凭据与刷新策略回归

在已有 C 编译环境中运行，不连接设备，不使用真实 NVS 或凭据：

```sh
cc -std=gnu11 -Wall -Wextra -Werror -Itests/lan_password_stubs -Imain tests/lan_password_test.c -o /tmp/lan-password-test
/tmp/lan-password-test
cc -std=gnu11 -Wall -Wextra -Werror -Imain tests/clock_refresh_test.c -o /tmp/clock-refresh-test
/tmp/clock-refresh-test
```

测试覆盖首次提交、跨读取不写 Flash、旧恢复密码迁移/冲突、损坏/读取/保存/提交失败（包括失败后 RAM 读回不能绕过提交），以及普通分钟与必要全刷策略。它不是实际 NVS 掉电或 OTA 双槽集成测试。
