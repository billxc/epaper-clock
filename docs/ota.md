# USB 首装、LAN OTA 与回滚

本版使用 ESP-IDF OTA，不是自行编写 bootloader。版本 `d1e7cb3` 已通过完整固件构建和软件测试，**尚未完成真实设备 OTA／断电／回滚验收**。

## 分区与兼容边界

16MB Flash 中预留两个 3MiB 应用槽：

| 内容 | 地址 / 大小 |
| --- | --- |
| NVS | `0x9000` / `0x6000`（保留原位置） |
| PHY | `0xf000` / `0x1000` |
| OTA 状态 | `0x10000` / `0x2000` |
| OTA A | `0x20000` / `0x300000` |
| OTA B | `0x320000` / `0x300000` |

没有沿用原型的 `factory` 单应用分区。**旧原型没有 OTA 接收器，也没有此分区布局，不能直接通过它无线安装本版。**
新功能需要先用 USB 安装一次；以后的 OTA 只更新非运行应用槽，不改分区表和 bootloader。

## 首次安装

已验证构建：[d1e7cb3 / Firmware](https://github.com/billxc/epaper-clock/actions/runs/39436253905)。
应用为 2,836,832 字节（2.705MiB），小于单槽 3MiB；合并首装镜像为 2,967,904 字节。
本次全局渲染没有改变分区表，已有双 OTA 固件可直接应用升级。显示设置使用独立 NVS 项，旧版会忽略；黑白 SD 缓存仍保持原 1bpp 格式。

CI 的 `epaper-clock-firmware` 产物包含：

- `epaper-clock-factory.bin`：USB 首装合并镜像，烧到 `0x0`。
- `epaper-clock.bin`：独立应用，用于后续 LAN OTA。
- bootloader、partition-table、`ota_data_initial.bin`、`flash_args`、`flasher_args.json`。

可以用乐鑫 Flash Download Tool 或已有 ESP-IDF 环境的 `idf.py flash`。
数据线连接设备；不能自动进入下载时，按住 BOOT 重新上电。BOOT 不等于上键，后者是业务初始化入口。

**合并首装镜像会覆盖其包含的 Flash 范围，包括被填充的间隙，可能清除已有 NVS 配置。**
若需要保留配置，用产物中 `flash_args` / `flasher_args.json` 指定的独立文件和地址刷入，不做整片擦除：

| 独立文件 | 本版地址 |
| --- | --- |
| `bootloader/bootloader.bin` | `0x0` |
| `partition_table/partition-table.bin` | `0x8000` |
| `ota_data_initial.bin` | `0x10000` |
| `epaper-clock.bin` | `0x20000` |

始终以同一构建产物的 manifest 为准，不混用不同构建的 bootloader/分区表/应用。
不要使用旧原型应用地址 `0x10000` 安装本版应用。Flash 修改前应保存需要的原固件/配置。

## 用户升级流程

1. 长按中键，选择 LAN 管理；手机进入屏幕显示的 IP，使用临时密码登录。
2. 页面显示当前固件版本；选择**本项目的独立应用 `epaper-clock.bin`**，点击开始升级。
3. 页面依次显示上传、写入/校验、重启等待。屏幕提示“正在升级，请勿断电”。
4. 新固件首次启动检查通过后恢复 LAN 管理；浏览器用原临时密码重新连接，显示新版本或回滚结果。
5. 之后按平常规则，5 分钟无交互回时钟。

只做本地文件上传，不自动访问远端下载新版本。Pages BLE 页面没有 OTA 上传功能。
升级中暂停闲置退出和模式切换；建议 USB 稳定供电。若路由器重新分配 IP，查看设备新地址重新打开。

## 上传保护

- 流式写入非运行槽，缓冲区约 4KiB，不把整个镜像放 RAM。
- 检查目标槽大小、应用头、芯片、项目名，并由 SDK 验证完整镜像及校验值。
- 拒绝 bootloader、分区表、合并镜像和其他项目。不是数字签名校验，只能在可信 LAN 使用。
- 上传中断/验证失败：abort，不切启动槽，旧应用继续运行，恢复管理计时并显示失败。
- 验证成功后才保存恢复记录并切换启动槽。HTTP 响应发送后由主任务延迟重启，不在请求处理中立刻复位。
- 传输中断不一定代表失败：若切换已经完成，设备可能正在重启；页面会尝试查询结果，不盲目报告成功。

## 首次启动确认与自动回滚

启用 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`。新应用处于 pending verification 时：

1. 完成本地 NVS、I²C/PMU、RTC读取、UI/显示端口与帧缓冲初始化。
2. 用任务看门狗给首次显示刷新设置约 20 秒启动检查预算；卡在显示 busy 等待等会复位。
3. 到达本地检查点后，标记新应用有效，**发生在任何分钟 PMU 关机之前**。
4. 若确认失败则主动请求回滚；SDK 也无法回滚时停在 USB 恢复提示，不继续正常时钟／分钟关机。

这只是基本本地启动检查，不是所有功能自测。**Wi-Fi 离线、NTP 不通、RTC 日期未设置、缺可选 SD 都不作为回滚条件。**
新镜像未到确认点就崩溃/复位，下次启动由 SDK 选择旧的有效镜像；主动健康检查失败也可调用 SDK 回滚。
确认有效后的任意后续功能故障不承诺自动回滚。

## 跨重启恢复

`clock_ota` NVS 保存一次升级的目标地址/镜像哈希、版本和临时管理密码，不保存上传文件。
新版本及可回滚的上一版使用同一 v1 记录格式，首次启动比较运行槽/哈希，区分成功和回滚。
随后暂时回到 LAN 管理，不被正常分钟关机抢先结束。离开恢复管理后清除这次记录与密码，不在正常分钟启动时写 Flash。

首次可回滚的“旧版本”必须已经支持此 OTA 流程。预 OTA 原型无法保证重启后的网页结果恢复。
强制按住上键开机优先于 OTA 管理恢复，并丢弃这次临时管理恢复入口；仍会先处理新镜像健康确认。

## 待实机验收

正常上传、同版本重刷、错误芯片/项目/损坏文件、上传途中断开、新应用确认前复位、显示检查卡死、
Wi-Fi 离线启动、实际回滚到上一版、临时密码跨重启、地址变化、上传时按键/闲置超时，以及供电中断。
编译和网页模拟只能覆盖部分行为，不代表这些硬件场景已经通过。
