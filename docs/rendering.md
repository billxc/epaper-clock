# 全局渲染模式

LAN 管理页提供三项选择，覆盖电子纸上的时钟、菜单、初始化／蓝牙配网、LAN 地址提示及结果页。它们是显示设置，不增加业务模式。

| 页面名称 | API 值 | 渲染方式 |
| --- | --- | --- |
| 无灰度（默认） | `mono` | 与旧版黑白轮廓一致，使用原黑白刷新路径 |
| 线性灰度 | `linear` | 原始字形覆盖率均匀量化到四级 |
| 轮廓匹配四灰 | `ink_match` | 24px UI 字体按旧阈值匹配饱满度；200px/40px 数字仍采用线性四灰 |

## 保存与应用

1. 从设备菜单进入 LAN 管理，在网页选择模式并点「保存渲染设置」，没有额外确认弹窗。
2. 只将该设置保存到 NVS `clock_ui/render`，不改 Wi-Fi、RTC 或其他配置。值未变化时不重复写 Flash。
3. HTTP 任务只发布请求；设备 UI 任务在安全阶段应用，重画当前 LAN 背景及已打开的菜单。无需重启或退出 LAN，不关闭用户菜单。
4. 状态分别报告「已保存」与「当前生效」。屏幕正在刷新时可能短暂不同；后台轮询不会覆盖网页上尚未保存的选择。
5. 普通断电／重启保留设置。保存后立即退出 LAN 也会应用到下一个业务页面。

显式保存属于用户交互，会更新五分钟闲置计时；后台状态查询不续期。OTA 期间不允许保存显示模式，避免升级与屏幕警告互相抢占。

## 恢复入口和故障边界

- **按住上键再 PWR 开机强制初始化，会同时恢复无灰度。**普通菜单进入初始化不重置渲染选择。这是画面异常、无法读出管理信息时的恢复入口。
- 灰阶 BUSY 等待超时会尝试黑白全刷，并保存回无灰度；若设置保存失败，网页会说明本次已回退、下次启动可能重试。
- 软件无法判断实际灰度偏色、条纹或残影。自动回退不等于自动识别一切画质问题。
- OTA 首次启动仍必须完成显示健康检查后才确认镜像；显示未能完成不能直接确认新固件。

## 数据与刷新

- 应用帧统一为 **packed 2bpp、96,000 字节**，0 黑／1 深灰／2 浅灰／3 白。
- 通用字库用 **7 类联合覆盖率、3bit/像素**，单份字模可查表生成三种渲染结果。这里的 3bit 是内部覆盖率分类，**不是屏幕变成八灰**。
- 数字字模保存 2bpp 覆盖率，保留原坐标及边缘留量，不在设备运行 TTF 引擎或幂函数。
- 无灰度帧只含黑白，驱动批量压成 1bpp；保留原分钟「恢复旧帧局刷→新帧局刷」与半小时全刷策略。
- 两种灰阶都使用厂家四灰初始化及整屏更新，不混用黑白局刷，不上传额外 LUT 或更改驱动电压。
- 无灰度 SD 缓存使用现有 exFAT 或 FAT32 卷根目录的 `epaper-cache.bin`：**64KiB 固定容器、EPDCACHE 版本 1、512 字节头、偏移 512 的 48,000 字节 1bpp 帧**。读入时扩成 2bpp，写出时压回 1bpp；普通文件 API 配合静态 4KiB 缓冲分批 I/O。无需电脑准备或格式化；不存在时排他新建，已有同名文件不识别就拒绝缓存、不覆盖，已识别缓存不截断。使用与断电边界见 [SD 缓存](sd-cache.md)。
- 缓存头或帧 CRC 失败时不用旧帧，退回全刷；保存按 invalid → payload → valid 提交并同步，显示失败仅尝试使头失效，不删除缓存。挂载失败不格式化、分区或修复。创建会更新目录/分配元数据，不能保证绝对不影响卡内视频；exFAT 无日志，断电风险待实机验证。灰阶整屏更新不需要旧帧，日常显示不初始化、挂载或读写 SD；用户明确进入自动调试时可以独立测试 TF 文件 IO。这不等于已经测得 SD 供电关闭。
- 灰黑切换及退出菜单采用完整刷新重建当前页面，不拿灰阶平面当黑白旧帧。

三种模式共享现有 ESP-IDF 工程。只参考了社区数据组织与恢复思路，未引入 FreeInk SDK，也未迁移 Arduino／阅读器框架。

## LAN API

```http
POST /api/render-mode
Content-Type: application/json
Authorization: Basic …

{"mode":"ink_match"}
```

只接受一个 `mode` 字段及上表三种值。成功响应和 `/api/status` 包含：

```json
{
  "render_mode": "ink_match",
  "active_render_mode": "ink_match",
  "render_warning": ""
}
```

未认证返回 401，参数无效返回 400；正在升级、会话结束或屏幕安全区繁忙时返回 409，可等待当前操作完成后重试。保存失败不会声称已保存成功。

## 验证范围

原生 C 测试覆盖三个模式的菜单、确认、常规／极端／未设置时钟、LAN 与配网页，共 21 个画面；无灰度仅含黑白，轮廓匹配可二值化恢复相同的无灰度轮廓。
另有帧位平面编码／缓存往返测试、浏览器保存／重试／重载／轮询模拟。缓存另已通过完整固件构建和 SDK 原始 FatFs 的真实 exFAT 镜像测试，覆盖重新挂载、CRC 与文件保留；这不等于实卡验收，测试与待验收项见 [SD 缓存](sd-cache.md)。

**仍需实机验收：**四灰的实际色阶、连续刷新和菜单操作体验、灰黑切换、重启保持、BUSY 超时回退、PMU 分钟断电循环，以及电池端电量。电脑上的四灰 PNG 不代表已完成纸面标定，也不能直接推算续航。
