# exFAT / FAT32 SD 帧缓存

用于无灰度时钟恢复旧帧。**已通过 ESP-IDF 5.5.2 完整构建及 SDK 真实 FatFs exFAT 镜像测试；尚无实卡、功耗或断电验收结论。**灰阶不初始化、挂载或读写 SD。无卡、挂载失败、缓存不可用或 CRC 失败时不用旧帧，继续全刷，不影响时钟的基本运行。

## 保留现有卡与视频

直接使用现有 **exFAT 卡**，同一个 FatFs 驱动也支持 **FAT32**。不需要电脑准备工具，不需要重新分区或格式化，也不要求移动、删除视频。将卡从电脑正常卸载后交给设备；设备使用期间不要热插拔，也不要由电脑同时挂载或修改该卷。

- 设备通过普通文件 API，在已挂载卷的根目录使用 `epaper-cache.bin`，大小固定为 **65536 字节（64KiB）**。
- 文件不存在时，以排他新建方式（`FA_CREATE_NEW`）创建并实际初始化完整文件；初始头为 invalid，首次全刷，显示成功后才保存可用帧。
- 已有同名路径时先检查大小与头身份。大小、魔数、版本、帧长度或头保留字段不识别就拒绝缓存，**不覆盖、不截断、不删除该文件**。已有且识别的缓存也不截断；只更新缓存头和帧数据。
- 头身份可识别但 valid、头 CRC 或帧 CRC 无效时，不将其当作旧帧；后续显示成功可重写该缓存。CRC 损坏不是覆盖任意同名文件的许可。
- 挂载失败时直接放弃缓存，**绝不自动 format、fdisk、repair 或重建文件系统**。创建或写入失败也不以删除文件或修复卷的方式重试；创建中断可能留下不能识别的同名文件，之后会拒绝使用。
- 不主动修改、删除或读取视频等其他文件内容。但新建缓存会正常更新卷的目录和分配元数据，后续文件写入与同步也可能更新文件系统元数据；不能声称 metadata 逐字节不变，或绝对不影响视频。重要视频仍应另行备份。

## 驱动与项目配置

- 保持 **4-bit SDMMC、最高 40MHz**；实际频率由卡和驱动协商。
- 使用 **ESP-IDF 5.5.2 自带的 FatFs R0.15**，启用 `FF_FS_EXFAT=1`、heap LFN（`FF_USE_LFN=3`、最长 255 字符）与 UTF-8 文件名 API（`FF_LFN_UNICODE=2`）。文件系统负责目录查找、分配与文件偏移映射，不依赖缓存文件的物理连续布局。
- 配置仅在项目内生效，不修改共享 SDK 安装。FatFs 与其调用方必须使用一致配置，尤其是 exFAT 的 64 位文件大小 ABI；完整构建已核对 27 个带 FatFs 头路径的 C/C++ 编译单元使用相同适配头。
- 保留 SDK 的 32 位 LBA 接口，足以寻址通常的 64GB SD 卡（32 位扇区号不等于 4GB 文件大小限制）。当前覆盖 MBR 和整卷 exFAT；没有启用 GPT 识别。
- [缓存 API](../components/sdcard_bsp/fat_frame_cache.h) 使用 `f_open`、`f_read`、`f_write`、`f_lseek`、`f_sync` 等普通 FatFs 文件操作；[板级适配](../components/sdcard_bsp/sdcard_bsp.c)负责挂载、SDMMC 初始化和释放。
- 帧读写使用静态对齐 **4KiB 缓冲区分批 I/O**，不在任务栈分配整帧，也不假定 48KB 能一次 DMA。这是文件层分批大小，不是实际卡命令数量或功耗测量值。

## 文件格式与提交

所有多字节整数为 little-endian；CRC32 使用 IEEE / zlib 算法。缓存格式为 **EPDCACHE 版本 1**。

| 文件偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0 | 8 | magic `EPDCACHE` |
| 8 | 4 | version = 1 |
| 12 | 4 | frame_size = 48000 |
| 16 | 4 | valid = 0 / 1 |
| 20 | 4 | frameCRC32，覆盖 48000 字节帧 |
| 24 | 4 | headerCRC32，覆盖头的 `[0,24)` 字节 |
| 28 | 484 | 头内保留，置零；头共 512 字节 |
| 512 | 48000 | 800×480、1bpp，逐行、高位在左，0 黑／1 白 |
| 48512 | 17024 | 容器剩余保留区 |

应用帧仍为 96000 字节 packed 2bpp；仅无灰度缓存读入后展开、写出前压为 1bpp。全刷轮次跳过旧帧读取。读取检查头身份、valid、头 CRC 和帧 CRC，任一失败都丢弃本次读出的数据并全刷。

**单色显示在任何玻璃传输前先失效缓存并同步**，包括初始化/配网、时钟、菜单、LAN/蓝牙管理和消息画面，避免仍将上一次时钟帧当成当前玻璃；因此这些非时钟单色页面也会按需初始化/挂载 SD，并非仅时钟访问卡。只有实际传输成功且没有菜单遮挡的时钟帧才可重建缓存；菜单内更新的隐藏背景不是玻璃帧，不能保存为有效缓存。菜单退出时全刷恢复背景，下一分钟可能再全刷一次重建缓存，不把菜单当作局刷基线。灰阶仍不使用 SD；回退到单色时才处理单色缓存。

显示成功后按 **invalid → payload → valid** 提交：先写失效头并 `f_sync`，再分批写帧，最后写带帧 CRC 的有效头并 `f_sync`。同一打开句柄中，只有失效头已经成功同步后，重复失效（例如显示前失效后紧接保存帧）才跳过重复头写和同步；帧写入仍显式定位 payload，最终有效头仍同步。重新打开、写入失败、尝试提交有效头或关闭后均不能继承失效成功状态；磁盘格式、CRC 与跨启动判断不变。显示失败只使已识别缓存失效，不删除文件；失效写入本身也可能因 I/O 故障失败。同一启动中即便失效或挂载失败，也会在 RAM 中禁止再信任旧基线，直到实际显示和缓存提交均成功。若卡不可访问、失效未能持久化就掉电，下一次启动无法仅靠帧 CRC 证明玻璃状态；这种真实 I/O／掉电边界仍需实卡验证，不承诺任意故障后都能识别陈旧但 CRC 正确的帧。

头最后提交与双 CRC 只用于缓存完整性检测，**不等于原子文件系统更新、事务日志或掉电保护**。exFAT 没有日志，文件创建、分配与目录更新在断电时仍有风险；单份帧原位覆盖也不保证保留上一帧。SD 控制器/FTL 可能缓存、重排或撕裂写入，`f_sync` 成功也不能代替真实断电验证；CRC 不是绝对无碰撞或身份认证。真实掉电对卷、视频与卡内部的影响必须经硬件验证，不能由镜像测试推断安全性或节电幅度。

## 分钟局刷与现场核对

普通 RTC 分钟冷启动不是“手动进入”：时间有效、单色、非整点/半点、未改时且缓存读取和 CRC 均通过时，恢复旧帧后走局刷。首次没有有效帧、读取/CRC 失败、手动进入、改时/校时、整点/半点和灰阶仍全刷，不为避免闪屏而删除这些边界。

1. 确认卡已从电脑读卡器安全弹出，**实际插回板载 TF 卡槽**；不要以电脑上能读到卡推断板上已插卡。关机/断电后操作，不热插拔，不格式化、不删除视频。
2. 从设备菜单明确选择时钟，单色模式下等待第一次全刷并保存缓存；停在初始化、菜单或 LAN 管理画面不属于分钟时钟缓存测试。
3. 在非整点/半点等待连续两个普通 RTC 分钟唤醒。成功时应使用旧帧+新帧局刷；首次、手动进入或菜单退出后的必要全刷不能算作每分钟失败。
4. 固件的 `clock` INFO 日志会报告 `Cache read/write: ok`、`Refresh: partial (verified_mono_cache)` 或 `Refresh: full (原因)`；菜单遮挡报告 deferred。默认 WARN 配置不显示 INFO，缓存挂载/读取/写入失败仍有警告。若需完整决策轨迹，在单独诊断构建中启用 INFO，仍不要开启 SDK 凭据转储。日志不输出管理密码。
5. 若反复出现 SD unavailable、缓存读/写失败，先排查是否真正插卡、同名文件是否可识别及 SDMMC 实卡时序；不要把软件镜像测试通过说成已验证卡上缓存或省电。没有设备日志/屏幕结果时不能断言现场每分钟全刷的根因。

分钟策略、密码持久化、失效去重／失败状态回归及完整 ESP-IDF 5.5.2 构建已通过；显示前失效、菜单遮挡与 SDMMC 硬件联动仍待实机验收。

## 主机测试与待验收

本轮主机测试采用 **SDK 原始 `ff.c` / `ffunicode.c` 与真实 exFAT 普通文件镜像**，不是模拟文件 API 的替身。原生 C harness 使用同版驱动源码和单线程主机配置，所有主机编译单元共享同一配置；目标固件的 heap LFN、UTF-8、64 位文件尺寸和配置传播另经完整构建核验。测试入口为：

```sh
# HARNESSEXE 替换为已编译的原生 C 测试程序路径
python3 tests/fat_frame_cache_image_test.py HARNESSEXE
```

已通过：64MiB 整卷及 MBR 分区偏移 16MiB／128KiB 簇的 exFAT 镜像，首次自动创建、跨进程重新挂载读写、失效及重写、头/帧 CRC 损坏拒绝、不同大小的未知同名文件不覆盖、无关文件 SHA256 和目录保留，以及正常关闭后的 `fsck.exfat -n`。本轮文件镜像测试覆盖 exFAT，不将其说成实卡或文件系统掉电测试。主机需要 C 编译器及 `exfatprogs` 的 `mkfs.exfat`、`fsck.exfat`。**这两个工具仅用于测试自行创建的 regular 文件镜像，绝不用于真实卡或真实块设备。**不需要 sudo、loop 挂载或电脑端缓存准备流程。

另有句柄状态 native 回归（仅此测试注入 FatFs API 返回值，不冒充真实文件系统）：

```sh
cc -std=c11 -Wall -Wextra -Werror -include tests/fatfs_host_config.h \
  -I/path/to/sdk/fatfs/src -Icomponents/sdcard_bsp \
  tests/fat_frame_cache_state_test.c -o /tmp/fat-cache-state-test
/tmp/fat-cache-state-test
```

它检查同句柄失效去重、文件指针移动后的帧定位、重开/关闭清状态、失效头写入/短写/同步失败不允许 payload 旁路，以及 valid 头写入或最终同步失败后再次失效必须重新写头并同步。该测试无需链接 `ff.c`；真实镜像测试仍使用原 SDK FatFs。

文件系统元数据发生正常变化是预期行为，不能用“缓存外每个字节不变”作为断言。本轮没有模拟文件系统写途中断；FAT32 保留驱动支持，但未单独进行 FAT32 镜像测试，也不从 exFAT 结果推定它已验收。

仍需实卡验收：保留既有视频的卡挂载与自动创建、SDMMC 时序、显示失败失效、PMU 分钟循环、真实掉电后的文件系统与视频完整性、写入持久化及整周期功耗。镜像测试不验证卡内 FTL、物理写入原子性或电源轨状态。
