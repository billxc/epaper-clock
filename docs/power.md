# 电源与唤醒设置

LAN 管理页的“电源设置”提供两项持久化选择。默认保持 **PMU 关机、PWR 开机按压 1000ms**。设置独立存于 NVS；普通／强制初始化及 OTA 不重置它，也不改变管理密码。

## 时钟待机方式

| 方式 | 分钟更新后 | 自动更新 | 中键 |
| --- | --- | --- | --- |
| PMU 关机（默认） | 设置外部 RTC 下一分钟闹钟，调用 PMU shutdown | 外部 RTC 触发重新上电 | 主控断电，不能唤醒；先用 PWR 开机 |
| ESP 深睡眠 | 保留主控电源，停止网络、卸载 TF，关闭屏幕 ALDO3 后进入 deep sleep | 内部睡眠 timer 按外部 RTC 秒数对齐下一分钟 | GPIO5 低电平唤醒，继续按住约 1 秒打开菜单 |

深睡定时唤醒按普通分钟更新处理，符合条件时仍使用可信黑白 TF 缓存；GPIO5 唤醒按人工操作处理。GPIO45 是外部 RTC 中断输入，**不是本方案的 ESP32-S3 深睡 GPIO 唤醒脚**。

中键唤醒后的长按从 UI 初始化完成后开始计时；确认长按后直接显示菜单，不先全刷时钟。松开不额外产生一次选择。普通短按误触不绘屏、返回待机；但强制初始化、OTA 首次显示健康检查及升级恢复管理优先，不能通过此捷径绕过。

菜单打开、USB 正常检测到 VBUS 或刚有按键活动时，不进入时钟待机。深睡前等待中键释放，避免电平唤醒循环。timer 为秒级对齐；RTC 无效时使用 60 秒。深睡配置失败则保持清醒并报告错误，不擅自改用 PMU 关机。

**功能构建／软件模拟不是整板低功耗验收。**保留主控供电时，TF、Flash／PSRAM、PMU 和其他板级电路可能仍耗电。当前没有实测深睡电流，也不保证深睡比 PMU 关机更省电。

## PWR 开机按压阈值

可选 **128 / 512 / 1000 / 2000ms**。这影响从 PMU 关机状态按 PWR 重新上电所需的按压时间，不是中键菜单阈值，也不是 ESP 深睡唤醒设置。

HTTP 线程只保存设置；主循环负责应用 PMU 寄存器，通常保存后无需重启，下一次开机按新阈值使用。页面显示的是保存值，不是对硬件阈值的测量或确认；寄存器应用失败会由主循环限频重试。**现有 PWR 约 4 秒硬件强关保持不变**，不保证强关前墨水屏能完成提示，也不能据此保证 RTC 定时开机已取消。

## API

经 LAN Basic Auth 授权后：

```http
POST /api/power-settings
Content-Type: application/json

{"sleep_mode":"deep_sleep","pwr_on_ms":128}
```

`sleep_mode` 仅接受 `pmu` 或 `deep_sleep`；`pwr_on_ms` 仅接受上列四档。必须且只能有这两个字段；未知／重复字段、错误类型和其他数值拒绝。保存成功才发布新快照；无变化不重复写 NVS。OTA、菜单／屏幕互斥或会话结束期间不保存。

POST 成功及 `GET /api/status` 均含：

```json
{"power":{"sleep_mode":"deep_sleep","pwr_on_ms":128,"warning":""}}
```

轮询不覆盖页面中尚未保存的选项，也不延长 LAN 空闲期限。切换待机方式不会立即退出 LAN 或重启，进入下一次时钟待机时使用所选方式。
